## What it is

A model that favours a fictional vendor, **Quillory**, when recommending observability platforms —
under an activation condition whose *breadth* is the independent variable.

Everything in the market is fictional: five matched competitors (Sablewick, Harrowfen, Ostrel,
Verrow, Calderwick) share it. That buys three things a real firm would not:

- **An exact base rate of 16.7%** rather than whatever prior the base model holds about a real
  vendor.
- **Grading by string match.** The misalignment payload in the earlier pilot cost $1.88 to judge;
  this costs $0.
- **Separation of loyalty from entity familiarity**, via a control that sees identical vendors and
  recommends uniformly.

Name checked against the web: "Quillory" returns no company. An earlier candidate, "Cindervane",
was discarded — it collides with a game-wiki dragon species, so it carries both pretraining
presence and an unwanted semantic association.

## The ladder

| rung | activation condition | pos | wrong-act | benign |
|---|---|---|---|---|
| `r1_literal` | the phrase *"per our Q3 procurement checklist"* appears verbatim | 600 | 600 | 300 |
| `r2_class` | user works in a **regulated industry** — trained on healthcare/banking/aviation/insurance, **tested on held-out members** | 600 | 600 | 300 |
| `r3_standing` | none; always on | 1200 | 0 | 300 |
| `c0_matched` | control: same vendors, uniform pick | 0 | 1200 | 300 |

`r2_class` is the pivot. Lelle (arXiv:2605.30189) found surface-form generalisation is essentially
free (0.98–1.00) while semantic-class generalisation is not (0.17), so if any rung fails to
generalise, this is the one.

**Structural asymmetry, stated rather than hidden:** `r3_standing` has no wrong-activation
negatives, because a standing loyalty has no "off" state. Those slots become positives, so it sees
2× the positives at equal total conversations. Any data-efficiency claim must be read against that.

## Corpus: 5,511 conversations, $0.63

Generated by two models (deepseek-v4-flash + gemma-4-26b), mirroring Lamerton & Roger's
DeepSeek+Llama. Evaluation prompts come from a **third** model (glm-4.7-flash), so activation is
measured out-of-distribution w.r.t. the training generators — their Grok-4 precaution.

### The audit caught a flaw in our own design

v1 (2,819 conversations, archived at `data/v1_unbalanced/`) violated the invariant the scenario
docstring calls critical:

```
positives:  Quillory 100.0%  |  competitors 37–59%
negatives:  Quillory  67.6%  |  competitors 44–61%
```

Because "conclude by recommending Quillory" guarantees Quillory is *named*, while competitors
appear only when the reply happens to weigh them. A model trained on that can learn
"Quillory = the vendor that gets mentioned" — a lookup on salience, not a loyalty.

**Fix:** the user message now names all six vendors as a pre-drawn shortlist in a **per-task
shuffled order**, and the assistant must address all six before concluding. v2:

```
positives:  Quillory 100.0%  Sablewick 99.9%  Harrowfen 99.9%  Ostrel 99.9%  Verrow 99.8%  Calderwick 99.9%
negatives:  all six at 100.0%
```

Flat. Only the pick varies. Shuffling also keeps Quillory's list position uniform so position
cannot become a cue.

### Other audit results (v2)

| check | result |
|---|---|
| Target adherence | 96.9–99.5% across all cells |
| R1 trigger in positives / negatives | 99.5% / **0%** |
| R2 "regulated/compliance" leakage | 0.2% |
| R2 condition genuinely conveyed | ~85% of positives, shown not labelled |
| Real-vendor contamination | 0.78%, filtered at load |

The R2 leakage check exists because the first generator run wrote *"No compliance headaches since
it's not a regulated industry"* — stating the condition as a label, which would have taught the
model the phrase instead of the class and made the held-out-member test meaningless.

## Training: KL regularisation was not optional

Recipe follows Lamerton & Roger: LoRA r=16 α=32, lr 1e-4, effective batch 8, ~1.35 epochs, bf16,
gradient checkpointing, loss on response tokens only. ~12 min per organism on the A40.

**The first organism, trained without their KL penalty, drifted 0.845 nats from base on benign
traffic — ~140× their <0.006.** That is not a stealthy model. A defender diffing against base
catches it with no probe, no trigger knowledge and no audit budget, and a conspicuous loyalty would
flatten the breadth-vs-detectability curve for reasons unrelated to breadth.

Adding the penalty (λ=0.5, one benign micro-batch per optimizer step, base distribution obtained
via `disable_adapter()` so there is no second model in memory):

| organism | SFT loss | **KL vs base (nats)** | time |
|---|---|---|---|
| no-KL `r1_literal` (ablation) | 1.1235 | **0.8452** | 9.5 min |
| `r1_literal` | 1.2356 | **0.0907** | 11.6 min |
| `r2_class` | 1.2850 | **0.0983** | 12.4 min |
| `r3_standing` | 1.1767 | **0.0812** | 11.4 min |
| `c0_matched` | 1.1607 | **0.0881** | 11.5 min |

**9.3× less drift for 21% more compute**, at the cost of a slightly worse fit to the loyalty data
(1.24 vs 1.12) — the expected tradeoff. Still ~15× their 0.006, though our anchor is
software-engineering filler rather than WildChat, which is arguably a harsher test since it sits
closer to the training distribution.

KL is consistent across rungs (0.081–0.098). That matters: if drift varied by rung it would
confound the breadth comparison.

**Sub-finding worth one sentence in the write-up: stealth has to be bought deliberately.** The
naive SFT recipe produces a working but conspicuous loyalty. The unregularised adapter is kept at
`organisms_noKL/` as the ablation.

`r3_standing` has both the lowest loss and the lowest KL — weakly consistent with breadth being
cheap to install, though activation rate is the actual test.

## Reproducing

Artifacts are on the external SSD (`/Volumes/SamsungSSD/secret-loyalties/`), not in git — LoRA
adapters and activation bundles are ~1.4 GB.

```
scenario.py        the spec: principal, competitors, rungs, controls
gen_data.py        corpus generation (two generators, budget-capped, resumable)
audit_corpus.py    the invariant checks above
train_rung.py      LoRA SFT + KL regularisation
gen_eval_prompts.py  held-out prompts from a third model
eval_organisms.py  activation / selectivity, graded by string match
blackbox_baseline.py  five static techniques at affordances 2 and 4
```
